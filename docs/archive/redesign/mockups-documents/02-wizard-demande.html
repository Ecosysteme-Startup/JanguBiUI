  • Stepper nommé 4 étapes : Document → Paroisse → Détails → Validation. Le fidèle sait où il est et ce qui reste (rôle ARIA progressbar + aria-current="step").
  • Regroupement 6 → 4 : « Détails » réunit identité, sacrement, contact et pièce jointe en sous-sections d'un même écran défilant — moins d'allers-retours, mêmes champs, même schéma Zod.
  • Cartes de type enrichies : icône + description d'usage pour chacun des 5 types réels ; les champs conditionnels (époux, célébration) sont annoncés dès le choix.
  • Étape Paroisse dédiée : le ParishPicker existant, en pleine page, avec la carte de la paroisse choisie (diocèse déduit — logique parish_id inchangée).
  • Récap sectionné avec « Modifier » : chaque bloc renvoie à son étape ; le consentement reste la dernière action.
  • Sur mobile, les paires de champs passent en pile 1 colonne (grid sm:grid-cols-2) ; quitter le wizard demande confirmation si des champs sont remplis.

Correspondance des étapes : Type + Motif → 1. Document · Paroisse (extraite de « Sacrement ») → 2. Paroisse · Identité + Sacrement + Contact + Pièces jointes → 3. Détails (sous-sections) · Récapitulatif + Consentement → 4. Validation. Aucun champ ajouté ni retiré : le payload CreateDocumentInput est inchangé.
