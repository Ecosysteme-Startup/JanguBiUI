Les partis pris UX, en résumé (détail et justifications dans le plan) :

  • 1. Le suivi d'abord. La question du fidèle est « où en est ma demande ? » — chaque écran y répond avant tout (métaphore suivi de colis).
  • 2. L'action requise remonte. Une demande info_requested attend le fidèle : elle sort du flux et porte son CTA.
  • 3. Moins d'étapes perçues. Wizard regroupé 6 → 4 étapes nommées, payload backend inchangé.
  • 4. Le document a une dignité. Coffre-fort = certificats avec sceau et référence, pas des lignes de liste.
  • 5. La paroisse pilote par l'urgence. File SLA alignée sur l'escalade backend existante — pas de kanban.
  • 6. La signature du curé est un acte. Niveau 2 mis en scène (panneau dédié), pas un item de menu.

Contenu métier exact : types baptism, first_communion, confirmation, religious_marriage, godparent · statuts submitted → under_verification → validated → document_deposited + branches info_requested / rejected · traitement niveau 1 (diacre / admin paroissial) puis niveau 2 (signature du curé).
